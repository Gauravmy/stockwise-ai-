# StockWise AI REST API

- **Base URL:** `http://localhost:8000`
- **Versioned prefix:** `/api/v1`
- **Interactive docs:** `GET /docs` (Swagger UI) and `GET /redoc`, generated by FastAPI from the code
- **Machine-readable schema:** `GET /openapi.json`

All examples below are **real responses** captured from the running app with the synthetic sample loaded. Long arrays are truncated with `…`.

## Conventions

- **JSON** for request and response bodies. CSV uploads use `multipart/form-data` with a `file` field.
- **Dates** are ISO `YYYY-MM-DD`. **Timestamps** are ISO-8601 in UTC (`…Z`).
- **Pagination**: list endpoints return `{ "items": [...], "total", "limit", "offset" }`.
- Every response carries an `X-Request-ID` header, which is also logged server-side.
- **Errors** always use the same shape. Stack traces and internal details are never returned.

```json
{"error": {"code": "invalid_request", "message": "Request validation failed.",
  "details": [{"field": "current_stock", "message": "Input should be greater than or equal to 0", "type": "greater_than_equal"}],
  "request_id": "bf8780cee015"}}
```

### Status codes

| Status | When |
|---|---|
| 200 | OK |
| 201 | A resource was created (upload, forecast, inventory settings) |
| 404 | `not_found` or `inventory_not_found` |
| 409 | `duplicate_import` or `inventory_exists` |
| 413 | `payload_too_large` (file over 5 MB or more than 200,000 rows) |
| 415 | `unsupported_media_type` (not a `.csv` file, binary content, or a wrong content type) |
| 422 | Validation errors (codes below) |
| 500 | `internal_error`, with a generic message |

The 422 error codes are:

- `invalid_request`
- `missing_required_columns`
- `ambiguous_columns`
- `malformed_csv`
- `empty_file`
- `invalid_encoding`
- `no_valid_rows`
- `insufficient_history`
- `no_history`
- `no_active_dataset`
- `invalid_date_range`

## Products

### `GET /api/v1/products`

Returns the products in the **active** dataset, with history statistics.

| Query parameter | Meaning |
|---|---|
| `search` | Substring match on ID or name |
| `category` | Exact category |
| `include_inactive` | Default `false` |
| `limit` | 1–500, default 100 |
| `offset` | Default 0 |

### `GET /api/v1/products/categories`

Returns the distinct categories, for example `["Accessories","Beverages","Electronics","Gifts","Home Office","Stationery"]`.

### `GET /api/v1/products/{product_id}`

Optional `start_date` and `end_date` query parameters filter `sales`. That series is zero-filled up to the dataset end date, and `observed: false` marks the filled days.

```bash
curl "localhost:8000/api/v1/products/SKU-1001?start_date=2025-06-28&end_date=2025-06-30"
```

```json
{"product_id":"SKU-1001","name":"Arabica Coffee Beans 1kg","category":"Beverages","unit_price":18.48,
 "history_days":547,"observed_days":547,"first_date":"2024-01-01","last_date":"2025-06-30",
 "total_quantity":23868.0,"avg_daily_quantity":43.6344,"has_inventory":true,"latest_forecast_id":1,"dataset_id":1,
 "sales":[{"date":"2025-06-28","quantity":54.0,"observed":true},{"date":"2025-06-29","quantity":58.0,"observed":true},
          {"date":"2025-06-30","quantity":43.0,"observed":true}]}
```

If `start_date` is after `end_date`, the response is `422 invalid_date_range`. An unknown product returns `404 not_found`.

## Datasets

### `POST /api/v1/datasets/validate`

A dry run: validates the file and returns the full report and a 20-row preview. **Nothing is stored.** The optional `duplicate_policy` query parameter is `exclude` (the default) or `keep`.

```bash
curl -X POST localhost:8000/api/v1/datasets/validate -F "file=@data/sample_sales_invalid.csv;type=text/csv"
```

```json
{"report": {
  "filename": "sample_sales_invalid.csv", "is_valid": true,
  "total_rows": 11, "accepted_rows": 4, "rejected_rows": 6, "duplicate_rows": 1, "aggregated_rows": 1,
  "invalid_dates": 2, "invalid_quantities": 2, "negative_quantities": 1, "invalid_product_ids": 1,
  "missing_values": {"date": 0, "product_id": 1, "quantity": 1, "unit_price": 0},
  "rejected_samples": [
    {"row_number": 5, "reasons": ["invalid date (expected YYYY-MM-DD)"],
     "values": {"date": "01/02/2025", "product_id": "SKU-2001", "quantity": "8", "unit_price": "4.50"}},
    {"row_number": 6, "reasons": ["quantity is not a number"],
     "values": {"date": "2025-01-03", "product_id": "SKU-2001", "quantity": "abc", "unit_price": "4.50"}}, "…"],
  "instructions": ["Use ISO dates in the form YYYY-MM-DD (e.g. 2025-03-31) and remove future dates.",
                   "Make sure every quantity is a plain number such as 12 or 3.5.", "…"],
  "column_mapping": {"date": "Date", "product_id": "Product ID", "quantity": "Quantity Sold", "unit_price": "Unit Price"},
  "products": ["…per-product coverage and missing dates…"], "warnings": ["…"], "preview": ["…"]

```

`row_number` is the line number in the file, counting the header as line 1.

### `POST /api/v1/datasets/upload` → 201

Takes the same input as `/validate`. It commits the accepted rows as a **new active dataset version** and returns `{ "dataset": DatasetDetail, "report": ValidationReport }`.

Failure examples:

- Wrong file type:

  ```json
  {"error":{"code":"unsupported_media_type","message":"Only .csv files are supported. Export your data as comma-separated values (CSV).","details":{"filename":"bad.txt"},"request_id":"714067e81178"}}
  ```

- Same file uploaded twice:

  ```json
  {"error":{"code":"duplicate_import","message":"This exact file was already imported as dataset 1 ('sample_sales.csv'). Activate that dataset instead of importing it again.","details":{"dataset_id":1},"request_id":"a40f587a9581"}}
  ```

- A required column is missing (`422 missing_required_columns`). `details` lists `missing`, `found_columns` and `accepted_names`.

### `GET /api/v1/datasets/sample`

Downloads `sample_sales.csv` (synthetic, seed 42) as `text/csv`.

### `POST /api/v1/datasets/sample/load` → 201

Imports the synthetic sample through the same validation and commit pipeline as a normal upload. Repeating the call returns `409 duplicate_import`.

### `GET /api/v1/datasets`

Lists dataset versions, newest first. Accepts `limit` (1–100) and `offset`.

### `GET /api/v1/datasets/{dataset_id}`

Returns the dataset summary plus its stored `validation_report`.

### `POST /api/v1/datasets/{dataset_id}/activate`

Makes that version the active dataset, and returns its summary.

## Forecasts

### `POST /api/v1/forecasts` → 201

Request body: `{ "product_id": string, "horizon_days": 1–90 (default 30) }`.

```bash
curl -X POST localhost:8000/api/v1/forecasts -H "Content-Type: application/json" -d "{\"product_id\":\"SKU-1006\",\"horizon_days\":7}"
```

```json
{
  "id": 9, "product_id": "SKU-1006", "product_name": "A5 Notebook", "dataset_id": 1,
  "horizon_days": 7, "selected_model": "random_forest", "confidence": "validated",
  "history_days": 547, "observed_days": 543, "history_start": "2024-01-01", "history_end": "2025-06-30",
  "forecast_start": "2025-07-01", "forecast_end": "2025-07-07", "total_forecast": 155.8552,
  "selected_mae": 3.9007757337958417, "baseline_mae": 10.428571428571429,
  "created_at": "2026-10-16T13:18:28.603160Z",
  "selection_reason": "random_forest had the lowest holdout MAE (3.90 vs baseline 10.43, 62.6% lower) over the same 28 holdout days.",
  "warnings": [],
  "limitations": ["Point forecasts only; no prediction intervals are produced.", "…"],
  "points": [{"date": "2025-07-01", "predicted_quantity": 29.0959}, {"date": "2025-07-02", "predicted_quantity": 30.2134}, "…"],
  "evaluations": [
    {"model_name": "moving_average", "role": "baseline", "is_selected": false, "evaluated": true,
     "mae": 10.428571428571429, "rmse": 12.317235311314212, "test_samples": 28,
     "train_start": "2024-01-01", "train_end": "2025-06-02", "test_start": "2025-06-03", "test_end": "2025-06-30",
     "holdout": [{"date": "2025-06-03", "actual": 32.0, "predicted": 23.0}, "…"], "warnings": []},
    {"model_name": "seasonal_naive", "role": "candidate", "is_selected": false, "mae": 6.642857142857143, "rmse": 8.839844859659989, "…": "…"},
    {"model_name": "random_forest", "role": "candidate", "is_selected": true, "mae": 3.9007757337958417, "rmse": 5.221373213241882, "…": "…"}
  ]
}
```

How each kind of history is handled:

| History | Result |
|---|---|
| 14–55 days | `confidence: "low"`; every evaluation has `evaluated: false` and `mae`/`rmse` set to `null`; a warning explains how much more data is needed |
| Fewer than 14 days | `422 insufficient_history` |
| Unknown product | `404` |
| No dataset loaded | `422 no_active_dataset` |
| `horizon_days` above 90 | `422 invalid_request` |

### `POST /api/v1/forecasts/batch` → 201

Request body: `{ "horizon_days": 1–90, "product_ids": [..] | null }`. A `null` list forecasts every product in the active dataset.

The response is `{ "created": [ForecastRunSummary], "failed": [{product_id, code, message}] }`. A failure for one product does not stop the batch.

### `GET /api/v1/forecasts`

Returns run summaries, newest first. Filters: `product_id`, `dataset_id`, `limit` (1–200) and `offset`.

### `GET /api/v1/forecasts/{forecast_id}`

Returns the full run, including points and evaluations, in the same shape as `POST`.

## Inventory

### `GET /api/v1/inventory`

Returns all inventory settings, each with the product's name and category.

### `POST /api/v1/inventory` → 201

```json
{"product_id": "SKU-1001", "current_stock": 250, "supplier_lead_time_days": 10,
 "safety_stock_days": 5, "safety_stock_quantity": null,
 "minimum_order_quantity": 100, "order_pack_size": 24, "coverage_days": 14, "overstock_threshold_days": 90}
```

| Field | Constraint |
|---|---|
| `current_stock` | ≥ 0 |
| `supplier_lead_time_days` | Integer, 0–365 |
| `safety_stock_days` | 0–365 |
| `safety_stock_quantity` | ≥ 0. Set **at most one** of the two safety-stock fields; setting both returns a 422 |
| `minimum_order_quantity` | ≥ 0 |
| `order_pack_size` | > 0 |
| `coverage_days` | 1–365 |
| `overstock_threshold_days` | 1–3650 |

Settings that already exist return `409 inventory_exists`. An unknown product returns `404`.

### `PUT /api/v1/inventory/{product_id}`

Takes the same fields without `product_id` and **replaces** the settings in full. If no settings exist yet, it returns `404 inventory_not_found`.

### `GET /api/v1/inventory/recommendations`

Optional filters: `risk` (one of `critical`, `high`, `moderate`, `low`) and `reorder_only=true`. Results are sorted by risk, then by days until stockout.

```json
{
  "product_id": "SKU-1001", "status": "ok", "forecast_run_id": 1, "forecast_horizon_days": 60,
  "forecast_confidence": "validated", "forecast_selected_model": "random_forest", "forecast_total": 2568.3204,
  "inventory": {"current_stock": 250.0, "supplier_lead_time_days": 10, "safety_stock_days": 5.0, "…": "…"},
  "recommendation": {
    "avg_daily_forecast": 42.8053, "lead_time_demand": 422.4326, "safety_stock": 214.0267,
    "safety_stock_method": "5 days of average forecast demand", "reorder_point": 636.4593,
    "protection_period_days": 24, "protection_period_demand": 1024.2125, "target_stock": 1238.2392,
    "order_up_to_gap": 988.2392, "reorder_needed": true, "recommended_order_quantity": 1008.0,
    "days_until_stockout": 5.74, "stockout_within_forecast": true, "days_of_cover": 5.84,
    "stockout_risk": "critical", "overstock": false,
    "explanation": [
      "Expected demand during the 10-day supplier lead time is 422 units; safety stock is 214 units (5 days of average forecast demand), so the reorder point is 636 units.",
      "Current stock (250) is at or below the reorder point (636). Replenishment is recommended to reduce the risk of a stockout.",
      "Target stock covers the lead time plus 14 days of coverage (1,024 units) plus safety stock = 1,238 units; ordering 988 units closes the gap.",
      "Adjusted to 1,008 units to respect the minimum order 100 and pack size 24 (rounded up).",
      "At forecast demand, stock runs out in about 5.7 days, before a new order could arrive."],

```

The `status` field takes one of three values:

- `ok`: a recommendation was computed.
- `not_configured`: the product has no inventory settings yet.
- `no_forecast`: the product has settings, but no forecast exists for the active dataset.

## Dashboard and insights

### `GET /api/v1/dashboard/summary`

| Query parameter | Range | Default |
|---|---|---|
| `period_days` | 1–90 | 30 |
| `history_days` | 7–730 | 90 |
| `category` | optional | none |

The response includes:

- the active dataset
- KPI counts: `total_products`, `products_at_risk` (critical + high), `products_requiring_reorder`, `products_overstocked`, `products_without_forecast`, `products_not_configured`
- `forecast_demand` (the sum of the first `period_days` of each product's latest forecast) and `forecast_period_warnings`
- `risk_counts`
- `demand_series`: aggregated history, then the summed forecast
- `highest_risk`, `recent_datasets`, `recent_forecasts` and `data_quality_warnings`

### `GET /api/v1/insights`

The optional `window_days` parameter (7–180, default 28) sets the comparison window. The response contains:

- `trends`: the last window vs the prior window, per product
- `monthly_by_category`
- `top_forecast`
- `risk_counts`
- `overstock`
- `reorder_priorities`, each item with its explanation
